## Where the texts live

| Part | Files | Picked by |
|---|---|---|
| Frame app | `android/frame/src/main/res/values-*/strings.xml` | The language chosen on the frame (setup wizard or Settings → Language), else the system language. |
| Web app | `web/src/lib/i18n/en.ts` (source) and `web/src/lib/i18n/catalogs/<code>.ts` | The language picker, else the browser's languages on the first visit, else the profile's language. |
| Server texts | `server/internal/i18n/locales/<code>.json` | `Accept-Language` for error texts; the push endpoint's locale for notifications; the frame's language (else the claiming user's) for the default frame name. |
| Sign-in e-mails | `server/internal/logtoboot/emails/<code>.json` | Logto, from `ui_locales` (the web app sends its language) or its sign-in page language. |

### How the language flows

- **Frame.** The setup wizard opens on a grid of all languages in their own names and switches the whole wizard the
  moment one is tapped. The choice is stored on the frame, sent as `locale` when the frame enrols, and, once the frame
  belongs to a family, written to the frame settings as `locale.language`. Changing the frame's language in the web
  app (frame settings → Display → Frame language) changes the frame too. The frame sends its language as
  `Accept-Language` on every request.
- **Web.** The first visit picks the best match from the browser's languages; the picker stores the choice and also
  saves it as the profile's `locale`, which the server uses for push notifications. Only English is bundled; each other
  language loads as its own small chunk. Dates, numbers, lists, plurals and relative times use `Intl` with the
  language's tag (`INTL_TAGS` in `locales.ts`).
- **Server.** Problem `title`s are translated per code (`problem.<code>`), and `detail`s are looked up by their English
  text, so `problem.New(code, "album changed since version %d", v)` needs no key of its own. Unknown languages fall back
  to English. The default name of a newly claimed frame uses the owner's first name in the frame's language
  ("Jeroen's frame", "Fotolijst van Jeroen", "Bilderrahmen von Jeroen").
- **Sign-in e-mails.** The bootstrap (`kinframe-server bootstrap-logto`) stores one template per language and type in
  Logto's e-mail template store (`PUT /api/email-templates`, Logto 1.27+), idempotently. Logto uses them when the
  sign-in's language resolves to one of them, and falls back to the English templates of the SMTP connector
  otherwise. Logto only resolves languages its sign-in page supports, so for some languages the e-mail stays English
  until Logto (or a custom language added in the Logto console) covers it.

## Right-to-left (Arabic, Hebrew)

- **Frame:** `android:supportsRtl="true"`; Compose mirrors layouts from the locale. Use `start`/`end`
  (`Alignment.*Start`, `padding(start = …)`), never left/right, for anything that follows reading order. Directional
  icons (`KinIcons.ChevronLeft/Right`, `Undo`) are built with `autoMirror`. Photos, the QR code and the frame code are
  not mirrored.
- **Web:** `<html dir>` follows the language (set before the first paint in `app.html` and on every switch). CSS uses
  logical properties (`inset-inline-start`, `margin-inline-end`, `padding-inline-*`, `text-align: start`); the few
  things that cannot be logical (the select arrow, the switch knob) have `[dir='rtl']` rules in `app.css`. Directional
  icons are listed in `MIRRORED` in `Icon.svelte`. Tab arrow keys follow the reading direction.
- `LocalizedScreenshotTest` renders the setup wizard and slideshow overlays in Arabic, Japanese, German, Russian and
  English to `android/frame/build/screenshots/l10n/` for review.

## Adding or changing a string

1. **Write the English text** in the source file: `values/strings.xml` (frame), `en.ts` (web), `locales/en.json`
   (server) or `emails/en.json` (e-mails). A new server problem detail needs no key: add its exact English text to the
   `details` of `en.json` (a test fails if a `problem.New` text is missing).
2. **Add it to every language.** Every test below fails until each language has the new key, so a change is never
   half-translated. If you cannot translate it, ask in the pull request; machine-assisted drafts are fine if you say so.
3. **Plurals:** Android `<plurals>` and web keys `<key>.one` / `<key>.other` must cover every CLDR category the
   language uses for whole numbers (Polish `few`/`many`, Arabic `zero`/`two`/`few`/`many`, Japanese only `other`; on
   the web the extra categories are extra keys such as `send.issues.few`). Android lint also wants the categories
   only decimals reach (Czech, Slovak and Lithuanian `many`); give them the `other` text. In languages where `one` also covers 21,
   31… (Russian, Croatian…), every form must show the number.
4. **Placeholders** must match English: `%1$s`/`%d` on Android (positional ones may be reordered), `{name}` on the
   web and in server messages, the same printf verbs in the same order in server details, `{{code}}` in e-mail
   subjects.
5. **Check:** `node tools/i18n/check-lang.mjs [codes…]` checks all four parts at once. The test suites enforce the
   same: `LocalizationTest` (Android, also checks that `values-iw`/`values-in` equal `values-he`/`values-id`),
   `catalogs.test.ts` (web), `internal/i18n` and `internal/logtoboot` tests (server).

## Adding a language

Add the code to `Locales.kt` (with its native name), `web/src/lib/i18n/locales.ts`, `i18n.Languages` in
`server/internal/i18n/i18n.go`, the language lists in `tools/i18n/check-lang.mjs`, the plural table in
`LocalizationTest.kt`, and the table above; then create the four translation files.

## Writing style

- Natural, short UI copy, not word for word. The frame's screen is 1024 × 600: keep button and title text about as
  long as English.
- One word per concept per language, across frame, web, server and e-mails (see the glossary).
- Address the user as the platform does in that language: informal where consumer apps are (Dutch "je", German,
  Danish, Swedish and Norwegian "du"…), formal where that is the norm (French "vous", Russian "вы"…), polite
  です・ます in Japanese and 해요체 in Korean. The quick replies a grandparent sends from the frame ("Miss you") are
  personal messages and may be informal even in formal languages.
- Names and frame names are inserted as they are, so constructions must not need to inflect them (no genitive
  endings or case suffixes on `{name}`); prefer "Frame · {name}" style or a noun in front.
- Keep "kinframe" lowercase and untranslated.
