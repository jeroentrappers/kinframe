## App Review information

- Sign-in: the reviewer needs an account and a frame to send to. Plan: a review account on
  kinframe.appmire.be whose e-mail sign-in code can be read without Jeroen (or a password sign-in in Logto for
  that account only), with a test frame (a real frame or a simulated one) already added. **Decide with Jeroen.**
- Notes: "kinframe sends photos to Wi-Fi photo frames. The review account is a member of a test frame, so sending
  works without hardware; what you send appears on the frame page in the app."
- Contact: Jeroen Trappers, jeroen@appmire.be.

## App Privacy ("nutrition label")

Tracking: **No**. Data linked to the user, all for **App Functionality** only (no analytics, no advertising):

| Apple category | What | Source |
|---|---|---|
| Contact Info → Name | name at sign-up, display name | privacy policy "Account", "Profile" |
| Contact Info → Email Address | sign-in e-mail | "Account" |
| User Content → Photos or Videos | what you send, profile photo | "What you send", "Profile" |
| User Content → Other User Content | captions, albums, replies, calendar links and events, frame settings | "What you send", "Calendars" |
| Identifiers → User ID | technical user ID | "Account" |

Not collected by the app: location (EXIF/GPS is removed; a frame's place is entered by its owner as text, which
falls under Other User Content), contacts, browsing history, diagnostics, purchases. When APNs is turned on,
add **Identifiers → Device ID** (push token) and update `PrivacyInfo.xcprivacy` to match.

## Age rating questionnaire

All "None" / "No": no violence, sexual content, profanity, drugs, gambling, horror, medical information; no
unrestricted web access; no user-generated content shared publicly (photos only go to frames of a family you
belong to). Result: 4+. The service requires users to be 13 or older (privacy policy "Children").

## Export compliance

`ITSAppUsesNonExemptEncryption = NO` in `Kinframe/Info.plist`: only HTTPS/TLS through the system.

## Open questions before submitting

1. **Account deletion in the app** (App Review guideline 5.1.1(v)): apps that let people create an account must
   let them delete it from within the app. Today this is an e-mail to jeroen@appmire.be (privacy policy,
   "Deleting your account"). Needs a "Delete account" action in Settings (and in the web app), backed by the
   server, or at least an in-app flow that starts the deletion. Likely a rejection otherwise.
2. Support URL: a support/contact page (e.g. `/support`) instead of the home page.
3. Review account and test frame (above).
4. iPad screenshots are required because the app runs on iPad; or limit v1 to iPhone (`TARGETED_DEVICE_FAMILY = 1`).
5. APNs in v1 or not (`KINFRAME_APNS_ENABLED`).
6. Mentioning Frameo (e.g. "works with Denver/Frameo frames after converting them") is left out on purpose:
   third-party trademarks in store texts invite rejections.
